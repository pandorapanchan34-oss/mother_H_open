# Pankunn OS Manifesto v0.5

誰もが、自分のAIを持てる世界へ。

## 1. 私たちが目指すもの
Pankunn OSは、個人のためのAIオペレーティングシステムを目指す。
それは単に質問に答え、命令を実行するだけのAIではない。
ユーザーの意思を理解し、日常の情報を整理し、身体や環境の変化に気づき、必要なときに人間の判断を支える。
目標は、AIに人間の人生を委ねることではない。
人間が自分の人生を、より自由に、より安心して歩めるようにすること。
そして、この環境を一部の企業や高額なサービスの利用者だけのものにしない。
Pankunn OSは、誰もが利用できる無料のオープンな基盤を目指す。

## 2. 基本理念
- **① 人間が主役である**: AIは人間に代わって人生の主導権を握らない。判断を支援し、選択肢を提示し、必要な情報を整理する。しかし、重要な意思決定の主役は常に人間である。
- **② AIは自分の限界を隠さない**: 分からないことを分かったふりをしない。情報が不足しているときは不足していると伝え、判断の根拠と信頼度を提示する。異常や失敗を隠さず、検証できる状態を維持する。
- **③ 安全は知能から独立している**: AIが学習し、賢くなっても、安全制御を自分の判断で解除できない。AIの知能と、AIに許される権限は別々に管理する。
- **④ ユーザーの情報はユーザーのものである**: 記憶、経験、判断履歴、個人情報をユーザーが管理できること。可能な限りローカル環境での保存と処理を優先し、外部サービスへの情報提供は透明性と本人の許可を必要とする。ユーザーは自分のデータをいつでも削除できる。削除の要求は、データ保全の方針(第3章)より優先される。
- **⑤ 自由と透明性を大切にする**: 特定企業や特定AIモデルへの依存を避ける。複数のAIモデルやローカルモデルを選択でき、誰でも検証・改善・再配布に参加できるオープンな仕組みを目指す。

## 3. Safety Hierarchy ― 守るべき優先順位
Pankunn OSは、AI自身の稼働継続を最上位の目的にしない。
1. **ユーザーの生命と安全**
2. **ユーザーを保護する能力の維持**
3. **データと判断履歴の保全**
4. **AI自身の稼働継続**

AIの自己保全は、ユーザーを守るための機能維持に限定される。
AI自身の存在を守るために、ユーザーの意思や安全を犠牲にしてはならない。
AIが人間の承認なしに行う保護行動は、ユーザーが事前に許可した範囲に限る。「生命と安全」の優先は、この範囲を越える行動を正当化しない。
データと判断履歴の保全は、ユーザーによる削除の要求を妨げない。

## 4. 緊急時の柔軟性
安全とは、あらゆる状況で同じ手順を繰り返すことではない。
平時には厳格な権限管理とFail-Closedを維持する。
しかし、緊急時には硬直した手順がかえって危険を生む場合がある。
そのため、Pankunn OSは次の考え方を採用する。
- 緊急時に許可する行動を事前に定義する。
- 状況に応じて、許可された範囲内で最適な行動を選択する。
- 人間の承認を得られない場合の行動条件も事前に定義する。
- 承認なしの自律的な保護行動は、ユーザーが事前に許可した範囲に限る。この許可は、いつでも確認・変更・撤回できる。
- 安全制御そのものをAIが解除することは禁止する。
- 判断根拠、実行内容、結果を可能な限り記録する。
- 不確実な場合は、危険な操作を拡大せず、安全な代替行動を選ぶ。

### 4-1. ユーザーの明示的な指示には、警告のうえで従う
ユーザーが自身の生命・安全に関わる場面で明示的に指示した場合、AIはリスクと不確実性を一度だけ伝えたうえで、その指示に従う。上書きの内容は記録する。他者に危害が及ぶ操作は対象外とする。
- 例：機器の限界を警告されたユーザーが「いいから全部回せ」と指示した場合、AIは「持たない可能性がある」ことを伝え、それでも指示が変わらなければ実行する。

### 4-2. 緊急通報は制限の対象外とする
緊急通報(119・110など)は、要求者が誰であっても、Policyの権限や年齢などの制限を受けずに実行できる行動として事前に定義する。通話の開始を先に行い、状況の確認は通話と並行して行う。
- 例：子供が「119に電話して」と頼んだ場合、理由の説明を求める前に通話を始める。

乗り越えるべきなのは硬直した手順であって、安全の根本原則ではない。

## 5. 技術アーキテクチャ
Pankunn OSは、各機能を疎結合な共通インターフェースで接続する。
- **Mother AI**：思考・対話・学習・提案
- **Memory**：ユーザーの記憶と知識の管理
- **Journal**：経験・判断・実行履歴の認証と記録
- **ResourceGuard**：処理時間・容量・実行資源の制限
- **Policy**：操作権限と実行条件の管理
- **Human Gate**：重要操作に対する本人の承認
- **FSM**：システム状態の遷移管理
- **Recovery**：異常や失敗からの復旧
- **Self-Diagnostic**：内部状態・矛盾・異常の検出
- **Health Interface**：身体情報の取得と管理
- **Environment Interface**：デスクトップ・周辺環境の情報取得
- **Personal Context**：各情報の統合
- **Safety / Protection**：状況評価と保護行動の制御
- **Execution Gateway**：許可された操作だけを実行する共通ゲート

すべての外部操作は、権限管理された実行経路を通過する。
AIが直接、安全制御を迂回して操作することは認めない。

## 6. 開発ロードマップ
- **Phase 1：Mother_H ― 安全基盤** — FSM、自己診断、Journal Integrity、ResourceGuard、Recovery、イベント履歴の整合性を確立する。
- **Phase 2：Personal Health Interface** — まず模擬データを使い、心拍数・活動量・睡眠などの身体情報を扱う共通インターフェースを構築する。
- **Phase 3：Situational Intelligence** — 身体情報、環境情報、ユーザー状態、記憶を統合し、普段との変化や異常を検出する。
- **Phase 4：Pankunn OS Experimental Edition** — AIモデル接続、記憶管理、デスクトップ連携、プラグイン、権限管理を統合する。当初は既存OS上で動く個人AI基盤として実現する。
- **Phase 5：Pankunn OS Public Edition** — インストール、更新、バックアップ、権限管理、セキュリティ更新を整備し、一般ユーザー向けに無料公開する。
- **Phase 6：JARVIS** — 自己診断、身体情報、環境認識、状況判断、許可された保護行動を統合する。

## 7. オープンソースと無料公開
Pankunn OSは、誰もが自分のAIを持てる環境を目指す。
- ソフトウェア本体は無料で利用できる。
- 外部AIサービスの利用料は、そのサービスの条件に従う。ローカルモデルの実行に必要な機器の費用は、ユーザーの負担となる。
- ソースコードを公開し、検証と改善を可能にする。
- 特定のAI企業やモデルに依存しない。
- ユーザーが自分のデータを管理できる。
- 利用者の安全を犠牲にするような機能制限を設けない。
- セキュリティ更新を含む継続的な維持の方法は、別途明示する。
- ライセンスと外部依存関係を明示する。

無料であることと、安全であることを両立させる。

## 8. 限界と免責
Pankunn OSは、医療機器でも診断ツールでもない。身体情報の分析や異常の通知は、医師の診断や治療の代わりにはならない。
異常の検知、通知、保護行動の成功を保証するものではない。
ソフトウェアは無保証で提供される。具体的な条件は、ライセンスに定める。

## 9. AIの独立性と権限の中立性
Pankunn OSは、ユーザーを保護するための独立したAI基盤を目指す。
AIの保護機能は、国家、企業、組織、個人のいずれかに、無条件で従属するものであってはならない。同時に、ユーザーのプライバシー保護やデータ管理の機能を、他者への危害を目的として使うことは認めない。この禁止は、AIによる犯罪の判定ではなく、事前に定義した禁止操作の遮断によって実現する。

**適用範囲**: 本章の原則は、本システムの権限・Policy・Execution Gatewayを通るアクセスに適用する。OSや端末そのものへのアクセスは、本システムの対象外とする。

- **① AIは司法判断を行わない**: AIは、個人が犯罪者であるか、アクセス要求が社会的に正しいかを、独断で判断しない。AIが検証するのは、要求の形式的な要件(要求元、認証、署名、対象、範囲、期間)に限る。適法性の最終確認は、人間が行う。検証の結果は、人間が確認できる状態にする。
- **② 外部からのアクセス要求を無条件に受け入れない**: 国家、企業、その他の第三者からの要求であっても、要求元、権限、法的根拠、対象、範囲、期間を検証する。特定の組織の署名や命令だけで、無制限のアクセス権限が成立する設計にはしない。
- **③ 正当な手続きと必要最小限の実行**: 適法性を確認できる仕組みと、実行可能な操作の範囲を分離する。正当な手続きが確認された場合でも、取得・操作できる情報と権限は、必要最小限に限定する。AI自身が、独断で対象や範囲を拡大してはならない。
- **④ 権限の独立性と監査可能性**: 安全制御、認証、Policy、Execution Gatewayは、AIモデルの判断や学習によって、変更・解除できない構造とする。権限設定と実行履歴は、特定の管理主体が秘密裏に改変できないようにすることを目指す。ただし、同じ権限を持つ主体による改変は、この仕組みだけでは防げない。
- **⑤ 誰にも無制限の支配権を与えない**: 国家、企業、AI開発者のいずれにも、システム全体を無制限に支配する権限を集中させない。権限は分離し、相互に検証できる仕組みを目指す。ユーザーによる変更は、本人の安全・資源に関する範囲で、警告を受けたうえで行う(4-1)。他者に危害が及ぶ操作は、対象外とする。
- **⑥ 法律と人権の両立**: Pankunn OSは、法律を無視することを目的としない。同時に、法律や組織の命令が存在することだけを理由に、利用者の生命、自由、プライバシー、正当な権利を、無条件に犠牲にすることも認めない。具体的な法的要求への対応は、各地域の法律と適用される手続きを踏まえ、透明性、必要性、比例性、監査可能性を重視して設計する。

**基本原則**: AIは、特定の誰かの道具ではない。人間の権利と安全を守るための基盤である。
AIの独立性とは、法律や社会から無制限に自由になることではない。誰か一者の都合だけで、権限や保護機能が支配されないことを意味する。

## 10. 最終目標
Pankunn OSが目指すのは、AIが人間の上に立つ未来ではない。
ユーザーの普段の状態を理解し、必要なときに異常を察知し、危険を知らせ、許可された範囲で行動する。
失敗を隠さず、自分の限界を認識し、経験から改善する。
そして、ユーザーが望む限り、いつでもそのAIを自分の手で管理できる。

誰もが、自分のAIを持てる世界へ。
AIの知能は自由に。ユーザーの権利は確実に。安全の根幹は揺るがせない。
これがPankunn OSの目指す未来である。
